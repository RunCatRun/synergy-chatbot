# Как запускать тесты

Документ объясняет, как проверить работу чат-бота автоматическими тестами:
какие команды вводить, что означает вывод, какой тест за что отвечает.

Команды приведены для Windows и оболочки PowerShell (в ней по умолчанию
открывается терминал VS Code). Перед запуском нужно: открыть терминал в
корневой папке проекта (там, где лежит `bot.py`) и активировать
виртуальное окружение — в начале строки должно стоять `(.venv)` или
`(venv)`.

---

## 1. Что такое эти тесты

Тесты — это небольшие проверки, которые сами подают боту фразы и
сверяют, в какую категорию он их отнёс. Если бот ответил как ожидалось,
тест «проходит»; если нет — «падает». Тесты не трогают интернет и не
меняют файлы проекта, запускать их безопасно сколько угодно раз.

Тесты запускаются программой **pytest**. Она устанавливается вместе с
остальными зависимостями (`pip install -r requirements.txt`). Проверить,
что она есть:

```
pytest --version
```

Если выводится номер версии — всё готово. Если пишет, что команда не
найдена, установить:

```
pip install pytest
```

---

## 2. Запуск всех тестов

Основная команда — просто:

```
pytest
```

### Что появится на экране

Строка из точек и итог. Пример нормального результата:

```
.............................................................. [100%]
138 passed, 2 skipped in 3.50s
```

Здесь:
- **каждая точка `.`** — один пройденный тест;
- **`138 passed`** — пройдено 138 тестов;
- **`2 skipped`** — 2 теста пропущены (это нормально, см. ниже);
- **`in 3.50s`** — время выполнения.

Важно: при обычном запуске тесты **не печатают подробностей** — только
эту итоговую строку. Отсутствие подробного вывода и есть признак успеха.
Главное, чтобы в конце было слово **passed** и не было слова **failed**.

### Про 2 пропущенных теста

Два теста проверяют векторную ветву уровня 3 и требуют модель spaCy с
векторами (`ru_core_news_lg`). На машине, где эта модель установлена,
они выполняются, и итог будет:

```
140 passed in 4.10s
```

Если у тебя установлена `ru_core_news_lg`, ты должен увидеть именно
**140 passed** без пропусков. Если видишь **138 passed, 2 skipped** —
значит, модель с векторами не подхватилась (стоит малая модель или
сработал запасной pymorphy3).

### Обозначения символов в выводе

| Символ | Значение |
|--------|----------|
| `.` | тест пройден |
| `F` | тест провален (failed) |
| `s` | тест пропущен (skipped) |
| `E` | ошибка при подготовке теста (error) |

Если появилась буква `F`, под строкой точек pytest подробно распишет,
какой тест упал, какую фразу подавали, что ожидали и что получили.

## 3. Подробный вывод: имена тестов

Чтобы увидеть список всех тестов по именам и статус каждого:

```
pytest -v
```

Вывод примет вид (фрагмент):

```
tests/test_level2.py::test_base[academic-Привет-greeting] PASSED
tests/test_level2.py::test_synonyms[academic-Где общага?-dormitory] PASSED
tests/test_level3.py::test_tfidf_empty_query PASSED
tests/test_level3.py::test_vector_backend_available SKIPPED (нужна модель ...)
```

Каждая строка — отдельная проверка с её результатом.

---

## 4. Запуск части тестов

Запустить тесты только одного файла:

```
pytest tests/test_level2.py
```

Запустить один конкретный тест (имя файла, два двоеточия, имя функции):

```
pytest tests/test_level3.py::test_tfidf_empty_query
```

Запустить все тесты, в имени которых есть слово (например, «synonym»):

```
pytest -k synonym
```

---

## 5. Сохранение результата в файл

Иногда вывод тестов удобно сохранить (например, чтобы приложить к
отчёту). В PowerShell:

```
pytest -v | Out-File -Encoding utf8 test_report.txt
```

В папке проекта появится файл `test_report.txt` с полным выводом в
кодировке UTF-8. Открыть его можно Блокнотом или в VS Code.

Чтобы одновременно видеть вывод на экране и записать в файл:

```
pytest -v | Tee-Object -FilePath test_report.txt
```

---

## 6. Полезные флаги

| Флаг | Что делает |
|------|------------|
| `pytest -v` | подробный вывод с именами тестов |
| `pytest -q` | сокращённый вывод (только точки и итог) |
| `pytest -x` | остановиться на первом провале |
| `pytest -s` | показывать то, что тесты печатают (`print`) |
| `pytest -k слово` | запустить тесты, в имени которых есть слово |

Флаги можно сочетать, например: `pytest -v -x`.

## 7. Что проверяет каждый файл тестов

Папка `tests/` содержит четыре файла. Каждый отвечает за свой уровень
или сторону работы бота.

### tests/test_bot.py — уровень 1 (базовый)
- распознавание двадцати типовых вопросов по ключевым словам (для
  обоих тонов ответов);
- приведение слов к начальной форме (лемматизация);
- удаление служебных слов (стоп-слов);
- ответ-заглушка при бессмысленном вводе.

### tests/test_level2.py — уровень 2 (средний)
- те же базовые вопросы плюс случай «сколько стоит магистратура»,
  который уровень 1 определял неверно;
- распознавание семи запросов с разговорными синонимами («общага»,
  «почём», «айти» и др.);
- приоритет категории-намерения при равенстве веса;
- память диалога: наследование темы уточняющим вопросом и смена темы
  при новом намерении.

### tests/test_robustness.py — устойчивость
- ответ на вопросы о возможностях бота («что ты умеешь», «помощь»,
  «справка», «хелп»);
- распознавание запросов с опечатками («общжитие», «магистратра»);
- наличие перечня тем в ответе-приветствии;
- распознавание команды выхода с опечаткой («выхд») и защита от
  ложного срабатывания на слове «вход».

### tests/test_level3.py — уровень 3 (продвинутый)
- каскад сохраняет правильные ответы уровня 2;
- TF-IDF распознаёт перефразировку при совпадении слов;
- пустой запрос не даёт ложного совпадения;
- *(требует модель с векторами)* векторный движок доступен и возвращает
  категорию;
- *(требует модель с векторами)* векторное сходство распознаёт
  перефразировку без общих слов.

Последние два теста — те самые, что пропускаются при отсутствии модели
`ru_core_news_lg`.

## 8. Проверка векторной ветви: check_vectors.py

Это отдельный скрипт (не тест). Он показывает, что векторное сходство
реально работает, и сравнивает его с TF-IDF на перефразировках без
общих слов. Запуск из корня проекта:

```
python check_vectors.py
```

### Ожидаемый вывод

Сначала строка о загруженной модели, например:

```
Движок NLP: {'engine': 'spacy', 'model': 'ru_core_news_lg', 'has_vectors': True}
```

Затем таблица сравнения двух методов, например (категории и числа
зависят от модели):

```
Фраза                                  | Вектор                 | TF-IDF
----------------------------------------------------------------------------------------
куда селят приезжих студентов          | dormitory (0.62)       | — (0.00)
во что встанет год учёбы               | cost (0.58)            | — (0.00)
...
```

Смысл: в столбце «Вектор» должны стоять осмысленные категории, а в
столбце «TF-IDF» — прочерки или низкие значения. Это показывает, что
векторный метод понимает смысл там, где лексический бессилен (у фраз
нет общих слов с ключевыми словами категорий).

Если вместо модели в первой строке указано `'has_vectors': False` или
`pymorphy3`, скрипт об этом предупредит: векторная ветвь требует модель
`ru_core_news_lg` либо `ru_core_news_md`.

Сохранить вывод скрипта в файл (PowerShell):

```
python check_vectors.py | Out-File -Encoding utf8 vectors_check.txt
```

## 10. Если pytest пишет «No module named 'chatbot'»

Это значит, что команда `pytest` не видит корень проекта. В проекте
для этого есть файл `conftest.py` в корневой папке — он добавляет
корень в пути поиска модулей. Если файл на месте, команда `pytest`
работает.

Запасной вариант, работающий всегда, даже без этого файла, — запуск
через модуль:

```
python -m pytest -v
```

## 11. Если ошибка «DLL load failed» при импорте numpy

Симптом: при запуске тестов уровня 3 (или `python bot.py` на уровне 3)
появляется `ImportError: DLL load failed while importing
_multiarray_umath: The parameter is incorrect` или похожая ошибка про
numpy либо scikit-learn.

Причина: Windows часто не может загружать скомпилированные библиотеки
(numpy, scikit-learn, spaCy) с сетевого пути (UNC, вида
\\сервер\папка) или с подключённого сетевого диска. Уровни 1 и 2 на
чистом Python от этого не страдают, а уровень 3 — страдает.

Решение: перенести проект на локальный диск (настоящий C:\, не сетевой)
и создать там новое виртуальное окружение:

```
robocopy "сетевой_путь\synergy-chatbot" "C:\dev\synergy-chatbot" /E /XD .venv __pycache__ .pytest_cache
cd C:\dev\synergy-chatbot
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt   # модель ru_core_news_lg ставится вместе с остальными
```

Проверка, что numpy грузится: `python -c "import numpy; print(numpy.__version__)"`.

Пока проблема не устранена, тесты уровня 3 автоматически пропускаются,
а тесты уровней 1 и 2 выполняются нормально. Бот на уровне 3 при этой
ошибке сам переключается на уровень 2.

## 9. Краткая шпаргалка

```
pytest                  запустить все тесты
pytest -v               то же, с именами тестов
pytest tests/test_level2.py     только тесты уровня 2
pytest -k synonym       только тесты со словом synonym в имени
pytest -v | Out-File -Encoding utf8 test_report.txt   сохранить в файл
python check_vectors.py проверить векторную ветвь уровня 3
```

Успех — это слово **passed** в итоговой строке и отсутствие **failed**.
